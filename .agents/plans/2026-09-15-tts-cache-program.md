## Goal

Личный open source проект: кэширующий прокси для TTS-провайдеров как основная часть, плюс тонкие клиенты — эталонный нативный iOS SDK для настройки и лёгкой интеграции в мобильное приложение, затем Kotlin/Android и JavaScript. Разбиение на предложения на новых платформах может быть проще, но качество кода и инфраструктуры везде одинаковое. Отдельный акцент: безопасность, устойчивость в облаке, качество кода, открытость и прозрачность, архитектура кода и архитектура деплоймента. Никаких связей со сторонними продуктами и никаких их упоминаний в репозитории.

## Success Criteria

- Прокси отдаёт повторные предложения с диска и синтезирует новые один раз, с изоляцией по предложениям: одно медленное предложение не роняет весь запрос.
- Прокси защищён: таймауты upstream и дедлайн всего запроса, лимит размера текста, токены на приложение с отзывом, базовые rate limits, singleflight на одинаковые предложения.
- Кэш ограничен: LRU-эвикция с настраиваемым лимитом размера, переполнение диска исключено.
- Провайдеры за абстракцией: общий интерфейс синтеза, ElevenLabs-совместимая реализация первая.
- Развёртывание распределённо-готовое: stateless-сервис плюс абстракция общего хранилища кэша, метка региона в ответах и метриках, SDK держит список эндпоинтов и переключается на следующий до прямого обращения к провайдеру. Минимальная топология — контейнер и compose, рядом переносимые манифесты оркестратора.
- Swift SDK как эталон: результат несёт источник аудио и детали отказа прокси для аналитики.
- Kotlin SDK и JavaScript-клиент воспроизводят общие векторы и эталонный ключ до любого сетевого кода.
- Гайд доводит чистый хост от нуля до раздачи по env-конфигу.
- Открытость: лицензия, contributing, архитектурные документы, публичный roadmap в трекере. В репозитории ноль упоминаний сторонних продуктов-примеров.
- `go test ./...` в `proxy/` и `swift test` в `swift/` зелёные после каждого среза.

## Context And Current Facts

- Монорепозиторий: `proxy/` — Go-сервис, `swift/` — SDK, `vectors/vectors.json` — общий контракт нормализации, эталонный ключ `v1-feab4a17bc7070e8` проверяется обеими сторонами.
- Текущий `POST /v1/synthesize` роняет весь запрос при первой ошибке upstream; нет авторизации, лимитов и коалесценции запросов.
- Хранилище пишет на диск без лимита и без удаления старого; upstream-слой знает только один ElevenLabs-совместимый провайдер; границы предложений сервер режет регуляркой, SDK — платформенными API.
- Связывающие решения лежат в `docs/decisions/0001`–`0008`; черновик следующего шага — в `docs/plan-next.md`.
- Трекер — GitHub Issues, словарь триаж-меток настроен; открытых задач сейчас нет.
- В `docs/`, `proxy/README.md`, `swift/README.md` есть упоминания стороннего продукта-примера — подлежат удалению до публичного релиза.
- Ответы владельца: эвикция — LRU; абстракция провайдеров — нужна; облако — сразу, удобно и современно; общий кэш между приложениями — оставляем; авторитет границ предложений — на усмотрение автора плана.

## Constraints And Non-goals

- Речь не должна ломать приложение, экономия вторична.
- Форма запроса `/v1/synthesize` не ломается: только аддитивные поля и заголовки.
- Ключи провайдера не лежат на устройствах сверх того, что уже есть у приложения-потребителя.
- Кэш на уровне предложений, не слов: пословная склейка убивает просодию.
- Серверный контракт — обычный HTTP, без привязки к iOS-only API.
- Non-goals раунда: живой второй регион (проектируем, за флагом), управляемая маршрутизация через DNS, пословный кэш.

## Key Decisions

- Релиз сразу как публичный open source, а не как внутренняя интеграция. Причина: так выбрано заранее, и это определяет порядок работ — доки, лицензия и деплой с нуля идут в том же релизе, а не следом.
- Распределённая схема сейчас, а не только один хост. Причина: так выбрано заранее. Следствие: интерфейс общего хранилища, stateless-сервис, метка региона, контейнерный образ, compose-минимум плюс переносимые манифесты оркестратора. Точный managed-таргет эталонного деплоя выбирается при реализации — это допущение. Это противоречит решению 0007 («без общего хранилища в этом раунде») — его предлагается заменить новым ADR.
- Эвикция — LRU с лимитом размера через env. Причина: прямой ответ владельца; диск без лимита рано или поздно роняет хост, а TTL хуже предсказуем по экономии, чем лимит байтов.
- Абстракция провайдеров сейчас. Причина: прямой ответ владельца; один захардкоженный провайдер закроет проект на единственного вендора. ElevenLabs-совместимая реализация остаётся первой и эталонной.
- Общий кэш между приложениями оставляем: app id в ключ не входит. Причина: прямой ответ владельца; так выше доля попаданий. Следствие фиксируем честно: клип, синтезированный для одного приложения, может отдать другое при совпадении всех шести звуковых полей.
- Границы предложений диктует сервер. Причина: разбиение различается от платформы к платформе, а ключ считается от нормализованного текста предложения — единый арбитр держит ключи стабильными. SDK делит текст своими API только для UX (превью, прогресс), вердикт сервера побеждает: ответ включает серверный список предложений и статусы по нему. Альтернатива «верит клиентским границам» отвергнута — даст рассинхрон кэша между платформами.
- Порядок SDK: сначала Swift до эталона, потом Kotlin, потом JavaScript. Причина: мобильный паритет доказывает переносимость векторов на второй нативной платформе, JS идёт тонким портом. Параллельное ведение всех трёх отвергнуто — даёт дрейф качества.
- Сначала закалка прокси, потом новые клиенты. Причина: второй SDK поверх хрупкого сервера умножает отказы.
- Выбор эндпоинта сначала замером latency в SDK, управляемая маршрутизация позже. Причина: не требует инфраструктуры и сохраняет self-hosting.
- Частичные результаты по предложениям вместо «всё или ничего». Причина: согласуется с цепочкой fallback — играем то, что есть, пробелы закрываем по голосовой политике продукта.
- Чистка упоминаний стороннего примера — отдельный нулевой шаг до публичного релиза. Причина: прямое требование владельца.

## Recommended Approach

Порядок: нулевой шаг — чистка и лицензия; затем закалка и защита прокси; затем LRU и абстракция провайдеров; затем распределённо-готовый деплой и наблюдаемость; затем Swift-эталон; затем Kotlin; затем JavaScript; финал — гайд деплоя, архитектурные документы и релиз. Каждый блок приземляется протестированным и задокументированным до старта следующего. Каждый новый клиент начинает с воспроизведения `vectors/vectors.json` и эталонного ключа.

## Work Plan

0. Чистка и open source гигиена. Удалить все упоминания стороннего продукта-примера из `docs/`, `README.md`, `proxy/README.md`, `swift/README.md`; добавить файл лицензии и заметки для контрибьюторов; завести публичный roadmap в GitHub Issues.
1. Изоляция по предложениям в прокси. Поверхность: `proxy/internal/http/server.go`. Серверный список предложений — авторитетный: возвращать склеенное аудио доступных предложений, сам список и карту статусов по нему; ни одна ошибка upstream не роняет весь батч.
2. Защита прокси. Таймаут upstream плюс дедлайн всего запроса, лимит размера текста, токены на приложение с отзывом, базовые rate limits, singleflight на одинаковые предложения. Выдача токена (регистрация) — только по приглашению; вход по готовому токену — без приглашения.
3. LRU и абстракция провайдеров. Поверхности: `proxy/internal/cache/store.go`, `proxy/internal/upstream/`. LRU с лимитом размера через env и счётчиками эвикций в метриках; общий интерфейс синтеза плюс ElevenLabs-совместимая реализация как первая.
4. Распределённая готовность. Абстракция хранилища кэша (локальный диск сейчас, общее хранилище позже без смены интерфейса), `REGION` env в заголовок ответа и метрики, контейнерный образ, compose-файл и переносимые манифесты оркестратора, описание метрик.
5. Swift SDK как эталон. Тип результата несёт источник аудио (память, диск, прокси, прямой провайдер, системный голос) и детали отказа прокси (хост, код, latency); упорядоченный список эндпоинтов с замером latency на старте и failover до прямого обращения. Клиентское разбиение — только для UX, границы сервера принимаются как факт.
6. Kotlin SDK. Порядок: нормализация, разбиение, ключ, построитель запроса против общих векторов и эталонного ключа; затем минимальный сетевой слой.
7. JavaScript-клиент. Тот же порядок: сначала векторы и эталонный ключ, затем fetch-обёртка с тегами источника.
8. Релиз. Гайд деплоя с нуля, документы архитектуры кода и деплоймента, версионирование через схему ключа, публичный changelog. Сюда же: новый ADR, заменяющий решение 0007.

## Validation Plan

- `go test ./...` в `proxy/` и `swift test` в `swift/` остаются зелёными после каждого среза.
- Фолт-инъекция против фейкового upstream: одно медленное предложение не блокирует остальные; лежащий прокси даёт меченый fallback, но не тишину.
- LRU доказывается тестом: при переполнении лимита вытесняется давно нечитанное, метрики считают эвикции.
- Второй провайдер доказывается заглушкой за тем же интерфейсом: контракт интерфейса держится без правок сервера.
- Новые клиенты без паритета векторов не принимаются: тесты векторов и эталонного ключа идут до сетевых тестов в каждом SDK.
- Проверка деплоя с нуля: чистый хост поднимается только по гайду, без устных дополнений.
- Контрольная прослушка склеенных фраз с реальным ключом провайдера на фиксированном наборе фраз до объявления качества готовым.
- Самый рискованный шаг валидации — прослушка ухом склеенного аудио. При провале гранулярность предложений пересматривается до расширения клиентов.

## Risks / Rollback

- Склейка может дать щелчки на границах mp3-фреймов. Смягчение: строгий порядок предложений и проверка ухом; откат только серверный, клиенты не трогаем.
- Токены на приложение добавляют операционки. Смягчение: один статический токен для минимальной топологии плюс процедура ротации в гайде.
- Общее хранилище вносит вопросы консистентности. Смягчение: регионы греют кэш независимо, кросс-региональных записей нет; общее хранилище только внутри региона.
- Общий кэш между приложениями светит один клип разным потребителям. Принято владельцем как цена экономии; при жалобе — изолирующий суффикс ключа отдельным изменением.
- Риск расползания «облако сразу». Смягчение: интерфейс хранилища и манифесты сейчас, второй живой регион за флагом.
- Откат релиза — тегами схемы ключа: смена схемы списывает старый кэш без ручной чистки.
